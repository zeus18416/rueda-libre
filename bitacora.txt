Roles en Rueda Libre:
- HTML: la estructura y el contenido. Ej: la tabla de tarifas o el formulario de reserva.

MiniReto 5 - Esquema de regiones

Estructura definida para las páginas:

Inicio:

  header (logo + nombre, nav con el menú)

  main

    section portada (h1)
    section ¿Quiénes somos?
    section Nuestros servicios -> 4 article (alquiler, eléctricas, recorridos, taller)
    section ¿Cómo alquilar?
    section Beneficios
    section Encuéntranos

  footer

Tarifas:

  header + nav

  main

    h1
    section Alquiler de bicicletas (tabla)
    section Recorridos guiados (tabla)
    section Información importante
    aside ¿Qué llevar?

  footer


Reservas:

  header + nav

  main

    h1
    section Contacto
    section Formulario de reserva
    aside Horario de atención

  footer

Estructura y semántica:

- El nav está dentro del header en todas las páginas.
- La sección "Encuéntranos" forma parte del main.
- En la página de reservas, el aside queda contenido dentro del main.
- No se utilizan elementos div. Únicamente se incluye un span para la insignia visual "Nuevo" en la tarjeta de eléctricas, ya que no existe un elemento HTML específico para ese concepto.

MiniReto 6 - Elección de controles de formulario

1. Tipo de bicicleta con radio buttons: se ofrecen tres opciones mutuamente excluyentes visibles de forma directa, compartiendo name="bicicleta".
2. Plan y recorrido con select: permite organizar las opciones desplegables manteniendo el formulario compacto.
3. Cantidad con input number: facilita el ajuste rápido mediante flechas y restringe la entrada de texto no numérico.
4. Políticas con checkbox para confirmación binaria y comentarios con textarea para texto multilínea libre.

Navegación por teclado:

Recorrido completo comprobado mediante Tab y Shift + Tab. El orden de navegación sigue la secuencia natural del documento: nombre, documento, correo, celular, fecha, tipo de bicicleta (navegación con flechas entre opciones), plan, cantidad, recorrido, comentarios, aceptación de políticas (espacio) y botón de envío (Enter). El flujo es lógico sin necesidad de atributos tabindex.

Limitación conocida: el formulario usa method="post" y action="#", pero GitHub Pages solo sirve archivos estáticos y no procesa el envío. La validación funciona en el navegador; con datos válidos la reserva no se guarda en ningún lado.


MiniReto 8 - Auditoría de accesibilidad

Puntos aplicados:

1. El logo del encabezado utiliza alt="" al ser un elemento decorativo situado junto al texto del nombre.
2. Descripciones alt detalladas en imágenes descriptivas (ej. "Mapa de la ruta entre el Parque del Río y el parque Koyo", "Bicicleta urbana de color negro").
3. Jerarquía de encabezados corregida: h1 único por página con el nombre principal, h2 para secciones y h3 para subsecciones estructuradas.
4. Tablas de tarifas configuradas con etiquetas caption descriptivas y h2 en sus respectivas secciones.
5. Textos de enlace explícitos e informativos (ej. "dónde encontrarnos", "Ver nuestra ubicación en Google Maps (abre en otra pestaña)").
6. Enlaces a sitios externos con target="_blank" complementados con rel="noopener".
7. Dirección de correo unificada en hola@ruedalibre.example a lo largo del sitio.
8. Corrección ortográfica global para asegurar una correcta lectura por sintetizadores de voz.

Atributo lang="es" configurado en el elemento html de todas las páginas.

Criterio de aplicación cromática:

- Texto principal y títulos: Texto principal sobre Fondo.
- Texto secundario (menú inactivo y horarios): Texto secundario sobre Fondo.
- Enlaces: color de Enlaces sobre Fondo.
- Botones: Texto principal sobre Botones; estado hover y foco en Fondo sobre Enlaces.
- Encabezados de tabla: Texto principal sobre Botones.
- Etiqueta "Nuevo": Fondo sobre Enlaces.
- El color de Botones no se usa como color de texto; sobre Fondo solo aparece en fondos de botón y bordes decorativos.
- Indicador de foco: contorno de 3 px en Texto principal, con 16.30:1 frente al Fondo. Se ve también en radios y casilla.

MiniReto 9 - Herencia

Configuración en body de tipografía principal, color del texto y fondo. Aplicación de tipografía Montserrat a h1, h2 y h3 mediante selector agrupado.

Verificación en DevTools > Computed:

- Propiedades heredadas: color (#F1F5F9) y font-family (Open Sans) se heredan correctamente en los elementos hijo.
- Propiedades no heredadas: padding-bottom y background-color no se heredan; los elementos mantienen sus valores por defecto (ej. background-color: transparent).



MiniReto 10 - Especificidad y reglas CSS

Reglas de navegación:

  #menu a  { color: var(--texto-secundario); }
  .activo  { color: var(--enlace); font-weight: 600; }


Cálculo de especificidad (id, clase, elemento):

  #menu a  -> (1, 0, 1)
  .activo  -> (0, 1, 0)


El selector #menu a prevalece al incluir un identificador ID. Para aplicar el estado activo manteniendo la especificidad adecuada sin recurrir a !important ni estilos en línea, se define:

  #menu a.activo -> especificidad (1, 1, 1).


Se añaden estados :hover y :focus en el menú (fondo color Enlaces con texto color Fondo y contorno Texto principal al enfocar), clase .boton para llamados a la acción principales y contorno de foco visible en los campos del formulario.


MiniReto 11 - Medición de componentes (Computed)

Ancho de contenedor principal: max-width 60rem (960 px) menos padding lateral de 16 px por lado = 928 px.

Comportamiento de tarjeta con width: 100%, padding de 24 px y borde de 1 px:

- Bajo content-box, cambiado solo en la tarjeta y con main todavía en border-box: 928 + 24 + 24 + 1 + 1 = 978 px (genera desbordamiento del contenedor).
- Bajo border-box: 928 px (el padding y el borde se integran dentro del ancho total).



MiniReto 12 - Posicionamiento y estructuración final

- La insignia "Nuevo" utiliza position: absolute contenida dentro de la tarjeta con position: relative.
- El botón de contacto de WhatsApp utiliza position: fixed en la esquina inferior derecha, compensado con un padding-bottom de 5rem en el body para evitar superposiciones con el pie de página.
- Hoja de estilos styles.css estructurada por bloques: variables en :root, estilos base, encabezado/navegación, componentes, formularios y elementos posicionados.
- Sitio publicado v1.0: https://zeus18416.github.io/rueda-libre/



Resumen de desarrollo

- Reto 1: Estructura del repositorio, carpeta de proyecto, index base y análisis de peticiones HTTP en la pestaña Network.
- Reto 2: Contenido de página de inicio con jerarquía de títulos, listas, imágenes con atributos alt y enlaces.
- Reto 3: Página de tarifas organizada con tablas y rutas relativas con ../.
- Reto 4: Integración de navegación global, pie de página y estructura inicial de reservas.
- Reto 5: Maquetación basada íntegramente en etiquetas semánticas HTML5.
- Reto 6: Formulario estructurado con fieldset, legend y controles accesibles.
- Reto 7: Validaciones nativas mediante atributos minlength, pattern, min, max y pruebas de entrada por teclado.
- Reto 8: Auditoría de accesibilidad WCAG, verificación de contraste de color y publicación en GitHub Pages.
- Reto 9: Sistema de diseño basado en variables CSS y fuentes de Google Fonts.
- Reto 10: Control de especificidad CSS, pseudo-clases de interacción (:hover, :focus) y estilos de estado.
- Reto 11: Implementación del modelo de caja box-sizing: border-box y ajuste de componentes.
- Reto 12: Posicionamiento relativo, absoluto y fijo, depuración final del código CSS e hito v1.0.
